# Security Policy

## Supported versions

Security reports are welcome for the latest source on the default branch and the latest tagged beta. This is an experimental project and does not currently offer a guaranteed response-time SLA.

## Reporting a vulnerability

Please do not publish exploit details in a public issue. Use GitHub's **Report a vulnerability** feature in the repository's Security tab if enabled. If private vulnerability reporting is unavailable, contact the repository maintainers through a private channel listed on the GitHub profile.

Include the affected version or commit, OS and Python version, minimal reproduction steps, expected and actual behavior, and impact. Do not include private archives, credentials, tokens, or unrelated personal data.

## Security scope

Relevant reports include path traversal, extraction outside the configured workspace, denial of service through archive processing, unsafe process execution, native-messaging trust-boundary failures, and unintended data disclosure.

Please allow maintainers reasonable time to investigate and prepare a fix before public disclosure.
